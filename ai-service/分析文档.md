# ai-service 架构分析文档

## 一、项目概述

| 项目 | 说明 |
|------|------|
| 类型 | Python FastAPI 微服务 |
| 端口 | 8000 |
| 用途 | 为 Todo 应用提供 AI 对话能力（LLM 代理），作为 Java 后端的 AI 网关 |
| 启动命令 | `uvicorn app.main:app --host 0.0.0.0 --port 8000` |
| 依赖 | fastapi, uvicorn, openai, httpx, pydantic |

## 二、文件结构

```
ai-service/
├── app/
│   ├── __init__.py              # 空
│   ├── main.py                  # FastAPI 入口，注册路由/中间件/启动逻辑
│   ├── config.py                # 配置类（Settings），读取 .env
│   ├── middleware.py             # API Key 鉴权中间件
│   ├── routes/
│   │   ├── __init__.py          # 导出 chat_router
│   │   └── chat.py              # /chat 和 /generate-title 端点
│   ├── llm/
│   │   ├── __init__.py          # 导出 LLMClient, OpenAICompatClient
│   │   ├── base.py              # LLMClient 抽象基类
│   │   └── openai_compat.py     # OpenAI API 兼容客户端实现
│   ├── session/
│   │   ├── __init__.py          # 导出 SessionManager
│   │   └── manager.py           # 对话 Session 管理（内存存储）
│   └── tools/
│       ├── __init__.py          # 导出 ToolRegistry, register_all
│       ├── registry.py          # 工具注册中心（注册/查找/执行）
│       ├── todo_tools.py        # 8 个 Todo 业务工具的声明 + 实现
│       └── context.py           # ContextVar 作用域令牌
├── .env / .env.example          # 环境变量配置
├── Dockerfile                   # Docker 部署
└── requirements.txt             # Python 依赖
```

## 三、核心执行顺序与调用链

### 3.1 应用启动流程 (`app/main.py`)

```
FastAPI 启动
  │
  ├── 1. 加载中间件（声明顺序）
  │     ├── auth_middleware    # 自定义鉴权（HTTP 中间件）
  │     └── CORSMiddleware     # CORS
  │
  └── 2. on_event("startup") → startup() 方法
        │
        ├── create_settings()                     # 读取 .env → Settings 对象
        │     └── _PROVIDER_DEFAULTS 补全 base_url 和 model
        │
        ├── chat_router.setup_deps(settings)      # 初始化 3 个核心依赖
        │     ├── OpenAICompatClient(settings)     # LLM 客户端
        │     ├── SessionManager()                 # 会话管理器（内存）
        │     └── ToolRegistry()                   # 工具注册中心
        │
        ├── todo_tools.register_all(registry)      # 注册 8 个工具
        │     └── 对每个 TOOL_DEFS 条目：
        │           registry.register(tool_def, partial(handler, settings))
        │
        └── asyncio.create_task(cleanup_loop())    # 后台任务：每小时清理过期会话
```

### 3.2 HTTP 请求处理流程

```
请求到达
  │
  ├── [auth_middleware] 鉴权中间件
  │     ├── /api/health, /docs, /openapi.json → 跳过
  │     └── 其他路径：校验 X-Api-Key 头 == INTERNAL_API_KEY
  │           ├── 未配置 INTERNAL_API_KEY → 500
  │           └── 不匹配 → 401
  │
  ├── [CORSMiddleware] 允许所有来源
  │
  └── 路由分发（/api 前缀）
        ├── GET  /api/health          → health()
        ├── POST /api/chat            → chat()
        └── POST /api/generate-title  → generate_title()
```

### 3.3 `/api/chat` 核心调用链（Tool Loop）

```
chat(request: ChatRequest)
  │  输入: { session_id, message, token, username, display_name }
  │
  ├── 1. 设置 scope token（ContextVar）
  │     └── scope_token.set(request.token)    # 供后续工具调用携带到 Java 后端
  │
  ├── 2. 会话管理
  │     ├── 无 session_id → session_mgr.create_session()  # 创建新会话 + 初始化 system prompt
  │     └── 有 username → 注入用户身份到 system prompt
  │
  ├── 3. 记录用户消息
  │     └── session_mgr.add_message(session_id, "user", request.message)
  │
  └── 4. 返回 StreamingResponse(event_generator())    # SSE 流式响应
        │
        └── event_generator() 协程（最多 5 轮 Tool Loop）
              │
              └── while tool_iterations < 5:
                    │
                    ├── a. llm_client.chat_stream(messages, tool_defs)
                    │     │  OpenAI API (stream=True)
                    │     │
                    │     └── 逐 chunk 解析：
                    │           ├── delta.content       → yield {"type": "text", "content": ...}
                    │           ├── delta.tool_calls     → 累积到 tool_calls_accumulator
                    │           ├── finish_reason="tool_calls" → yield {"type": "tool_call", ...}
                    │           └── finish_reason="stop" → yield {"type": "done", ...}
                    │
                    ├── b. 收到 tool_call 事件
                    │     ├── yield 给客户端（SSE：前端可看到 AI 正在调工具）
                    │     ├── tool_registry.execute(tool_name, tool_args)   # 执行工具
                    │     │     └── 查找注册的 handler → handler(**arguments)
                    │     │           └── todo_tools 中对应的 async 函数
                    │     │                 ├── _create_todo(...)    → POST /api/todos
                    │     │                 ├── _search_todos(...)   → GET /api/todos?q=...
                    │     │                 ├── _get_statistics()    → GET /api/dashboard/overview
                    │     │                 ├── _get_todo_detail()   → GET /api/todos/search?q=...
                    │     │                 ├── _list_projects()     → GET /api/projects
                    │     │                 ├── _list_teams()        → GET /api/teams
                    │     │                 ├── _generate_report()   → POST /api/reports/generate
                    │     │                 └── _get_calendar_events()→ GET /api/todos/calendar
                    │     │
                    │     ├── yield tool_result 给客户端
                    │     ├── 将 assistant_msg + tool_result 追加到 messages
                    │     └── break → 下一轮循环（LLM 再次调用）[最多 5 轮]
                    │
                    └── c. 无 tool_call → 结束循环
                          └── session_mgr.add_message(session_id, "assistant", full_response)
                          └── yield {"type": "done", "content": full_response}
```

### 3.4 `/api/generate-title` 调用链

```
generate_title(request: GenerateTitleRequest)
  │
  ├── 构造 messages：[system prompt, user message]
  ├── llm_client.chat_stream(messages, [])    # 无工具
  │     └── 逐 chunk 拼接回复文本
  └── 截取前 50 字符 → 返回 { "title": "..." }
```

## 六、关键设计要点

1. **Tool Loop 机制**：最多 5 轮迭代，每轮 LLM 可能返回文本或工具调用。有工具调用时，执行工具后将结果送回 LLM 继续推理，直到 LLM 返回纯文本为止。

2. **会话内存模型**：SessionManager 将所有对话存在内存字典中，重启即丢失。每小时清理超过 24 小时的旧会话。

3. **Scope Token 传递**：使用 `contextvars.ContextVar` 实现请求级 token 隔离，确保并发请求不会串 token。

4. **流式响应**：使用 Server-Sent Events (SSE)，前端可实时看到 AI 打字效果和工具调用过程。

5. **多 Provider 支持**：通过 OpenAI 兼容接口支持 DeepSeek、OpenAI、Ollama、OpenRouter 四种后端，通过 `.env` 的 `LLM_PROVIDER` 切换。

6. **API Key 鉴权**：通过 `X-Api-Key` 头校验，`INTERNAL_API_KEY` 为空时服务拒绝所有请求（返回 500），防止未配置时误用。

7. **身份注入**：在 system prompt 中注入用户名/显示名称，让 AI 知道在和谁对话，可实现个性化回复。
